# Лабораторная работа №3. Cost per Efficiency игроков NBA (Apache Spark)

## Задача

Даны три датасета:

| Файл | Содержимое |
|---|---|
| `players.csv` | игроки: `_id` и полное имя `name` |
| `salaries_1985to2018.csv` | зарплата игрока за сезон (1985–2018) |
| `Seasons_Stats.csv` | статистика игрока за сезон |

Нужно:

1. Посчитать эффективность игрока за сезон: **Efficiency = PTS + TRB + AST**
   (очки + подборы + передачи).
2. Посчитать цену за единицу эффективности:
   **Cost per Efficiency = зарплата за сезон / эффективность за сезон**.
3. Сохранить полученный датасет в Parquet с разбиением по годам (partition discovery).
4. Прочитать Parquet и вывести топ-5 самых выгодных игроков (с наименьшим Cost per Efficiency) за каждый год.

## Стек

- Java 25 (через Gradle toolchain)
- Apache Spark 4.2.0 (`spark-sql_2.13`)
- Gradle 9.6 + плагин Shadow (сборка jar для `spark-submit`)
- Docker Compose: кластер Spark Standalone (master + worker) на образе
  `spark:4.2.0-scala2.13-java25-ubuntu`

## Запуск

Исходные CSV лежат в каталоге `data/`. Программа принимает два необязательных аргумента:
каталог с CSV (по умолчанию `data`) и каталог для результата (по умолчанию `output`).

### В кластере Spark (Docker Compose)

1. Собрать jar. Spark подключён как `compileOnly`, потому что в кластере он уже есть:

   ```bash
   ./gradlew clean build
   ```

   Получится `build/libs/nba-cost-efficiency.jar`.

2. Поднять кластер. Каталог `output` должен быть доступен на запись пользователю
   `spark` внутри контейнера:

   ```bash
   mkdir -p output && chmod 777 output
   docker compose up -d
   ```

   Веб-интерфейсы: master — http://localhost:8080, worker — http://localhost:8081.

3. Отправить задачу в кластер:

   ```bash
   docker compose exec spark-master /opt/spark/bin/spark-submit \
     --class org.example.Main \
     --master spark://spark-master:7077 \
     --deploy-mode client \
     /opt/spark-apps/nba-cost-efficiency.jar /opt/spark-data /opt/spark-output
   ```

Каталоги, которые монтируются в оба контейнера:

| На хосте | В контейнере | Назначение |
|---|---|---|
| `build/libs` | `/opt/spark-apps` | jar приложения |
| `data` | `/opt/spark-data` (только чтение) | исходные CSV |
| `output` | `/opt/spark-output` | результат в Parquet |

Файлы результата создаёт пользователь контейнера (uid 185), поэтому с хоста их не удалить.
Перед повторным запуском (в том числе локальным) каталог чистится через контейнер:

```bash
docker compose exec spark-master sh -c 'rm -rf /opt/spark-output/*'
```

Остановить кластер:

```bash
docker compose down
```

### Локально

Для локального запуска Spark подключается к задаче `run` отдельной конфигурацией
`sparkLocal`. Мастер `local[*]` выбирается автоматически, если его не задал `spark-submit`.

```bash
./gradlew run
```

В обоих случаях результат записывается в `output/cost_per_efficiency/`, а топ-5 по годам
выводится в консоль.

## Алгоритм

### 1. Чтение данных (`DataLoader`)

| Источник | Колонки после чтения |
|---|---|
| `players.csv` | `playerId` (из `_id`), `name` |
| `salaries_1985to2018.csv` | `playerId`, `year` (из `season_end`), `salary` |
| `Seasons_Stats.csv` | `year`, `name` (из `Player`), `team` (из `Tm`), `pts`, `trb`, `ast` |

Год в `Seasons_Stats` — это год окончания сезона (например, 1990 — это сезон 1989-90),
поэтому он сопоставляется с `season_end` из таблицы зарплат.

### 2. Эффективность за сезон

Статистика группируется по `(name, year)`, считается `efficiency = pts + trb + ast`.

### 3. Зарплата за сезон

Зарплаты группируются по `(playerId, year)` и соединяются с `players` по `playerId`,
чтобы получить имя.

### 4. Cost per Efficiency

Зарплата соединяется с эффективностью по `(name, year)`. Записи с нулевой эффективностью
отбрасываются (на ноль делить нельзя), затем считается
`costPerEfficiency = round(salary / efficiency, 2)`.

### 5. Сохранение в Parquet

```java
data.repartition(col("year"))
    .write()
    .mode(SaveMode.Overwrite)
    .partitionBy("year")
    .parquet("output/cost_per_efficiency");
```

На диске получается по каталогу на каждый год (33 года, 1985–2017):

```
output/cost_per_efficiency/
├── _SUCCESS
├── year=1985/part-....snappy.parquet
├── year=1986/part-....snappy.parquet
└── ...
```

Сама колонка `year` в файлы не пишется: её значение хранится в имени каталога.

### 6. Чтение Parquet и топ-5

При чтении `spark.read().parquet(path)` Spark находит каталоги `year=...`
(partition discovery) и восстанавливает из них колонку `year`. Схема прочитанного датасета:

```
root
 |-- playerId: string
 |-- name: string
 |-- salary: long
 |-- pts: double
 |-- trb: double
 |-- ast: double
 |-- efficiency: double
 |-- costPerEfficiency: double
 |-- year: integer          <- восстановлена из имён каталогов
```

Топ-5 строится оконной функцией:

```java
Window.partitionBy("year").orderBy(col("costPerEfficiency").asc(), col("name").asc())
```

После этого `row_number()` и фильтр `rank <= 5`. Имя во вторичной сортировке нужно, чтобы
результат был одинаковым при равных значениях.

## Особенности данных и как они обработаны

1. **Звёздочка у имени.** В `Seasons_Stats` к именам членов Зала славы добавлена `*`
   (`Michael Jordan*`). Перед сопоставлением она удаляется.

2. **Игрок сменил команду по ходу сезона.** В статистике у такого игрока есть строка
   по каждой команде и итоговая строка `Tm = TOT`. Строка `TOT` не используется,
   а **PTS, TRB и AST усредняются по командам**. Если за сезон игрок получал зарплату
   в нескольких командах, **зарплата тоже усредняется**.

3. **Полные тёзки.** В `Seasons_Stats` нет id игрока, поэтому связать статистику с
   зарплатой можно только по имени. В `players.csv` 43 имени принадлежат разным людям
   (Eddie Johnson, Marcus Williams, Chris Johnson, Michael Smith и т. д.). Без обработки
   статистика двух разных людей склеивалась бы: например, «Eddie Johnson» оказался бы
   первым в 1985 году с эффективностью 4507. Поэтому пара `(name, year)` отбрасывается, если:
   - в статистике за год у имени несколько строк по разным командам и нет строки `TOT`
     (значит, это разные люди, а не обмен);
   - в таблице зарплат за год этим именем называются несколько разных `playerId`.

   Если тёзки играли в разные годы, их сезоны не теряются.

4. **2018 год.** Статистика заканчивается на сезоне 2016-17, поэтому зарплатам за 2018 год
   сопоставить нечего и этого года в результате нет. Итог охватывает 1985–2017.

## Выводы

- Самые выгодные игроки — почти всегда новички или игроки на минимальных контрактах,
  которые много играли: Mark Jackson (1988), Gilbert Arenas, Carlos Boozer (2003–2004),
  Monta Ellis (2007–2008), Isaiah Thomas (2012–2014), Nikola Jokic (2017).
- Cost per Efficiency первой строчки со временем растёт: с ~50 $ за единицу в середине 1980-х
  до ~300–600 $ в 2010-х. Это отражает рост зарплат в лиге.
- В 1990 году в топе одни звёзды с зарплатой ~1 млн $ (Stockton, Drexler, Price). Это
  особенность данных: в таблице зарплат за 1990 год всего 64 записи (в соседних годах
  их больше 300), и все они от 1 млн $. Игроков на маленьких контрактах за этот год нет.

## Ограничения

- Метрика считается по сумме за сезон, без учёта числа игр. Поэтому в топ попадают игроки
  с короткими контрактами и очень малой зарплатой (например, Dahntay Jones в 2016:
  8 819 $ за 20 единиц эффективности). Если нужно, можно добавить фильтр по минимальному
  числу игр (`G`) или минут (`MP`).
- Связь статистики с зарплатой идёт по имени, поэтому неоднозначные сезоны тёзок
  исключены из расчёта, а не разнесены по конкретным игрокам.
