# Лабораторная работа №3. Cost per Efficiency игроков NBA (Apache Spark)

## Задача

Даны три датасета:

| Файл | Содержимое |
|---|---|
| `players.csv` | игроки: `_id` и полное имя `name` |
| `salaries_1985to2018.csv` | зарплата игрока за сезон (1985–2018) |
| `Seasons_Stats.csv` | статистика игрока за сезон |

Нужно:

1. Посчитать эффективность игрока за сезон: **Efficiency = PTS + TRB + AST**
   (очки + подборы + передачи).
2. Посчитать цену за единицу эффективности:
   **Cost per Efficiency = зарплата за сезон / эффективность за сезон**.
3. Сохранить полученный датасет в Parquet с разбиением по годам (partition discovery).
4. Прочитать Parquet и вывести топ-5 самых выгодных игроков (с наименьшим Cost per Efficiency) за каждый год.

## Стек

- Java 25 (через Gradle toolchain)
- Apache Spark 4.2.0 (`spark-sql_2.13`)
- Gradle 9.6 + плагин Shadow (сборка jar для `spark-submit`)
- Docker Compose: кластер Spark Standalone (master + worker) на образе
  `spark:4.2.0-scala2.13-java25-ubuntu`

## Запуск

Исходные CSV лежат в каталоге `data/`. Программа принимает два необязательных аргумента:
каталог с CSV (по умолчанию `data`) и каталог для результата (по умолчанию `output`).

### В кластере Spark (Docker Compose)

1. Собрать jar. Spark подключён как `compileOnly`, потому что в кластере он уже есть:

   ```bash
   ./gradlew clean build
   ```

   Получится `build/libs/nba-cost-efficiency.jar`.

2. Поднять кластер. Каталог `output` должен быть доступен на запись пользователю
   `spark` внутри контейнера:

   ```bash
   mkdir -p output && chmod 777 output
   docker compose up -d
   ```

   Веб-интерфейсы: master — http://localhost:8080, worker — http://localhost:8081.

3. Отправить задачу в кластер:

   ```bash
   docker compose exec spark-master /opt/spark/bin/spark-submit \
     --class org.example.Main \
     --master spark://spark-master:7077 \
     --deploy-mode client \
     /opt/spark-apps/nba-cost-efficiency.jar /opt/spark-data /opt/spark-output
   ```

Каталоги, которые монтируются в оба контейнера:

| На хосте | В контейнере | Назначение |
|---|---|---|
| `build/libs` | `/opt/spark-apps` | jar приложения |
| `data` | `/opt/spark-data` (только чтение) | исходные CSV |
| `output` | `/opt/spark-output` | результат в Parquet |

Файлы результата создаёт пользователь контейнера (uid 185), поэтому с хоста их не удалить.
Перед повторным запуском (в том числе локальным) каталог чистится через контейнер:

```bash
docker compose exec spark-master sh -c 'rm -rf /opt/spark-output/*'
```

Остановить кластер:

```bash
docker compose down
```

### Локально

Для локального запуска Spark подключается к задаче `run` отдельной конфигурацией
`sparkLocal`. Мастер `local[*]` выбирается автоматически, если его не задал `spark-submit`.

```bash
./gradlew run
```

В обоих случаях результат записывается в `output/cost_per_efficiency/`, а топ-5 по годам
выводится в консоль.

## Алгоритм

### 1. Чтение данных (`DataLoader`)

| Источник | Колонки после чтения |
|---|---|
| `players.csv` | `playerId` (из `_id`), `name`, `birthDate` |
| `salaries_1985to2018.csv` | `playerId`, `year` (из `season_end`), `teamName` (из `team`), `salary` |
| `Seasons_Stats.csv` | `year`, `name` (из `Player`), `age` (из `Age`), `team` (из `Tm`), `pts`, `trb`, `ast` |

Строки `Seasons_Stats`, где имя игрока заканчивается на `*`, отбрасываются сразу при чтении
(подробнее в разделе «Преобразования данных»).

### 2. Ключ соединения: Year + Player + Age + Tm

Статистика соединяется с остальными таблицами по четырём полям `Seasons_Stats`:
`Year`, `Player`, `Age`, `Tm`. В зарплатах и `players.csv` таких колонок напрямую нет,
поэтому для каждой записи о зарплате они вычисляются:

| Поле статистики | Откуда берётся для зарплаты |
|---|---|
| `Year` | `salaries.season_end` |
| `Player` | `players.name` (через `salaries.player_id` = `players._id`) |
| `Age` | из `players.birthDate` и года сезона (см. ниже) |
| `Tm` | из `salaries.team` через таблицу соответствия `TeamAbbreviations` |

**Возраст.** В `Seasons_Stats` возраст игрока считается на 1 февраля года окончания сезона,
причём день рождения 1 февраля ещё не засчитывается. Эквивалентная формула:

```
age = year - year(birthDate) - (1, если игрок родился в феврале–декабре, иначе 0)
```

Формула проверена на данных: из 11 866 записей, где совпадают год, имя и команда, возраст
совпадает в 11 864. Два расхождения — ошибки в исходных данных (например, у Vincenzo
Esposito в 1996 году дата рождения и `Age` не согласуются на год). Если брать возраст ровно
на 1 февраля, перестают сходиться 64 игрока, родившиеся 1 февраля.

**Команда.** В зарплатах указано полное название (`Portland Trail Blazers`), в статистике —
аббревиатура (`POR`). Соответствие задано в `TeamAbbreviations` для всех 38 названий из
таблицы зарплат. Только одно название зависит от года: `Charlotte Hornets` — это `CHH`
до 2002 года включительно и `CHO` с 2015 года (в 2005–2014 команда называлась
`Charlotte Bobcats`, `CHA`).

### 3. Зарплата и статистика за команду

- Зарплаты группируются по `(playerId, year, teamName)`. Если одна команда платила игроку
  дважды за сезон (два контракта), суммы складываются. Затем присоединяется `players`,
  вычисляются `age` и `team`.
- Из статистики берутся строки по командам (`Tm != TOT`).
- Зарплата и статистика соединяются inner join по `(year, name, age, team)`. Получается
  строка на каждую команду, за которую игрок и играл, и получал зарплату.

### 4. Сезон игрока и Cost per Efficiency

Строки по командам группируются по `(playerId, name, year, age)`:

- `salary`, `pts`, `trb`, `ast` — **среднее** по командам (если игрок за сезон играл
  в нескольких командах);
- `teams` — список команд через запятую.

Затем считается `efficiency = pts + trb + ast`, записи с нулевой эффективностью
отбрасываются (на ноль делить нельзя), и считается
`costPerEfficiency = round(salary / efficiency, 2)`.

### 5. Сохранение в Parquet

```java
data.repartition(col("year"))
    .write()
    .mode(SaveMode.Overwrite)
    .partitionBy("year")
    .parquet("output/cost_per_efficiency");
```

На диске получается по каталогу на каждый год (33 года, 1985–2017):

```
output/cost_per_efficiency/
├── _SUCCESS
├── year=1985/part-....snappy.parquet
├── year=1986/part-....snappy.parquet
└── ...
```

Сама колонка `year` в файлы не пишется: её значение хранится в имени каталога.

### 6. Чтение Parquet и топ-5

При чтении `spark.read().parquet(path)` Spark находит каталоги `year=...`
(partition discovery) и восстанавливает из них колонку `year`. Схема прочитанного датасета:

```
root
 |-- playerId: string
 |-- name: string
 |-- age: integer
 |-- teams: string
 |-- salary: long
 |-- pts: double
 |-- trb: double
 |-- ast: double
 |-- efficiency: double
 |-- costPerEfficiency: double
 |-- year: integer          <- восстановлена из имён каталогов
```

Топ-5 строится оконной функцией:

```java
Window.partitionBy("year").orderBy(col("costPerEfficiency").asc(), col("name").asc())
```

После этого `row_number()` и фильтр `rank <= 5`. Имя во вторичной сортировке нужно, чтобы
результат был одинаковым при равных значениях.

что усредняется и почему. Цифры посчитаны по исходным CSV.

### Сводка

| # | Датасет | Преобразование | Сколько затронуто |

| 2 | `Seasons_Stats` | удаление пустых строк (нет `Year` или `Player`) | 67 строк |
| 3 | `Seasons_Stats` | удаление членов Зала славы (имя заканчивается на `*`) | 1 528 строк, 127 игроков |
| 4 | `Seasons_Stats` | итоговые строки `Tm = TOT` не используются | 1 481 строка с 1985 года |
| 5 | `Seasons_Stats` | пустые PTS/TRB/AST заменяются на 0 | 295 строк, все до 1985 года |
| 6 | `salaries` | вычисление `Age` из даты рождения и `Tm` из названия команды | все строки |
| 7 | `salaries` | две записи от одной команды за сезон суммируются | 2 случая |
| 8 | соединение | inner join по `Year + Player + Age + Tm` | совпало 11 863 из 14 161 записи о зарплате |

### 1. Колонки и типы

CSV читаются целиком как строки, затем приводятся к нужным типам и именам:

| Исходная колонка | Новая колонка | Тип |
|---|---|---|
| `players._id` | `playerId` | string |
| `players.name` | `name` (`trim`) | string |
| `players.birthDate` | `birthDate` (формат `MMMM d, yyyy`, напр. `June 24, 1968`) | date |
| `salaries.player_id` | `playerId` | string |
| `salaries.season_end` | `year` | int |
| `salaries.team` | `teamName` | string |
| `salaries.salary` | `salary` | long |
| `Seasons_Stats.Year` | `year` | int |
| `Seasons_Stats.Player` | `name` (`trim`) | string |
| `Seasons_Stats.Age` | `age` | int |
| `Seasons_Stats.Tm` | `team` | string |
| `Seasons_Stats.PTS`, `TRB`, `AST` | `pts`, `trb`, `ast` | double |

Остальные колонки (позиция, проценты бросков и т. д.) не используются.
`Year` в `Seasons_Stats` — это год окончания сезона (1990 — сезон 1989-90), поэтому он
сопоставляется с `season_end`, а не с `season_start`.

### 2. Пустые строки статистики

В `Seasons_Stats.csv` 67 пустых строк: в них заполнен только номер строки (первая безымянная
колонка). Они удаляются фильтром `year IS NOT NULL AND name IS NOT NULL`.

### 3. Члены Зала славы (`*` в имени)

В `Seasons_Stats` к именам членов Зала славы добавлена `*` (`Michael Jordan*`). Таких игроков
127, строк 1 528. Все эти строки удаляются сразу при чтении:

```java
.filter(not(col("Player").endsWith("*")))
```

Из-за этого не сопоставляются 452 записи о зарплате: Michael Jordan, John Stockton,
Clyde Drexler, Joe Dumars, Dominique Wilkins и другие.

### 4. Строки `TOT`

У игрока, которого обменяли, в статистике есть строка за каждую команду и итоговая строка
`Tm = TOT` (сумма по командам). Строки `TOT` не используются: в зарплатах команды `TOT` нет,
и соединение идёт по конкретной команде.

### 5. Пустые PTS, TRB, AST

В ранних сезонах подборы и передачи не учитывались, и в 295 строках есть пустые значения.
Они заменяются на 0 (`coalesce`). Все такие строки относятся к годам до 1985, поэтому на
результат это не влияет.

### 6. Age и Tm для зарплат

Описано в разделе «Алгоритм», шаг 2.

### 7. Две записи от одной команды

В 2 случаях одна команда платила игроку дважды за сезон (два контракта), например
Luis Scola в Houston Rockets в 2015 году. Эти суммы складываются в зарплату за команду.

### 8. Соединение по 4 полям

Из 14 161 записи о зарплате (после группировки по игроку, году и команде) со статистикой
совпадает 11 863. Остальные отбрасываются:

| Причина | Записей |
|---|---:|
| нет статистики за этот год (игрок не сыграл ни одного матча) | 923 |
| 2018 год: статистика заканчивается на сезоне 2016-17 | 551 |
| игрок — член Зала славы (`*` в статистике) | 452 |
| игрок не играл за эту команду (отчислен или обменян до начала сезона) | 366 |
| пустое название команды | 4 |
| возраст не совпадает из-за ошибки в исходных данных | 2 |

Статистика за 1950–1984 тоже не попадает в результат: за эти годы нет зарплат, и при
inner join ей не с чем соединиться. В результате остаются 1985–2017, это 33 партиции
`year=...`.

Ключ из 4 полей уникален: в статистике нет двух строк с одинаковыми
`Year + Player + Age + Tm`, а в зарплатах ни один ключ не принадлежит двум разным
`playerId`. Поэтому полные тёзки (в `players.csv` 43 имени у разных людей, например два
Eddie Johnson в 1985 году) разделяются автоматически по возрасту и команде.

Зарплата от команды, за которую игрок не играл, в расчёт не входит. Например, Mark Davis
в 2000 году получил 100 000 $ от Miami Heat (отчислен до начала сезона) и 6 000 $ от
Golden State Warriors, где и сыграл сезон. Учитываются только 6 000 $ и статистика за GSW.

### 9. Игрок сменил команду по ходу сезона

Если после соединения у игрока за сезон несколько команд (таких сезонов 118), зарплата и
PTS, TRB, AST **усредняются** по командам (зарплата округляется до целого, статистика до
2 знаков). Например, игрок с 300 очками в одной команде и 100 в другой получает
`pts = 200`. Список команд сохраняется в колонке `teams`.

### 10–11. Итоговый расчёт

Записи с `efficiency = 0` удаляются, чтобы не делить на ноль. Cost per Efficiency
округляется до 2 знаков: `round(salary / efficiency, 2)`.

## Выводы

- Самые выгодные игроки — почти всегда новички или игроки на минимальных контрактах,
  которые много играли: Mark Jackson (1988), Gilbert Arenas, Carlos Boozer (2003–2004),
  Monta Ellis (2007–2008), Isaiah Thomas (2012–2014), Nikola Jokic (2017).
- Cost per Efficiency первой строчки со временем растёт: с ~50 $ за единицу в середине 1980-х
  до ~300–600 $ в 2010-х. Это отражает рост зарплат в лиге.
- В 1990 году в топе только игроки с зарплатой от 1 млн $ (Mark Price, Jeff Malone,
  Otis Thorpe). Это особенность данных: в таблице зарплат за 1990 год всего 64 записи (в соседних годах
  их больше 300), и все они от 1 млн $. Игроков на маленьких контрактах за этот год нет.

## Ограничения

- Метрика считается по сумме за сезон, без учёта числа игр. Поэтому в топ попадают игроки
  с короткими контрактами и очень малой зарплатой (например, Dahntay Jones в 2016:
  8 819 $ за 20 единиц эффективности). Если нужно, можно добавить фильтр по минимальному
  числу игр (`G`) или минут (`MP`).
- Связь идёт по вычисленным полям: возраст считается из даты рождения, команда — по таблице
  соответствия названий. Если в исходных данных есть ошибка в дате рождения или названии
  команды, запись не сопоставится.
- Члены Зала славы (имена со `*` в `Seasons_Stats`) исключены из расчёта целиком.
